Configuration

Project file (lazyshell.yml)

KeyWhereDescription
shellrootShell used to run commands. Default: $SHELL, else /bin/sh.
env_fileroot, sessionA path or a list of paths to .env files. Later files override earlier ones; a missing file is ignored.
groupsrootList of - name: … entries declaring session groups.
sessionsrootRequired, at least one session. Names must be unique.
namesessionSession name.
commandsessionCommand to run.
groupsessionGroup the session belongs to, to start/stop/restart several at once.
cwdsessionWorking directory, relative to the folder of the config file.
envsessionInline variables.
autostartsessionStart the session when the daemon starts. Default: false.
typesessionservice (default, long-running) or task (runs to completion).
depends_onsessionList of session names to start, and wait for, before this one.
readyserviceReadiness probe: command, plus an optional timeout (30, 30s, 2m; default 60s).

Full example

shell: /bin/zsh
env_file: .env
groups:
  - name: backend
  - name: frontend
sessions:
  - name: db
    group: backend
    command: docker compose up postgres
    autostart: true
  - name: api
    group: backend
    cwd: ./api
    command: cargo watch -x run
    env_file: [.env.api, .env.api.local]
    env:
      RUST_LOG: debug
  - name: web
    group: frontend
    cwd: ./web
    command: npm run dev

Environment precedence

Lowest to highest: root env_file < session env_file < session env. Use lazyshell env <name> to print what a session actually receives.

.env syntax

  • KEY=value, with an optional export prefix.
  • # starts a comment.
  • Double-quoted values support the escapes \n \t \" \\; single-quoted values are literal.
  • No variable interpolation.

Reloading

Press L in the TUI or run lazyshell reload. Running sessions are left unchanged; a ~ next to a session means its config changed: restart it to apply the change.

Dependencies

sessions:
  - name: install
    type: task
    command: pnpm install
  - name: db
    command: docker compose up postgres
    ready:
      command: docker compose exec -T postgres pg_isready -h localhost
      timeout: 60s
  - name: api
    command: pnpm start:dev
    depends_on: [install, db]

Starting a session also starts its dependencies. What it waits for depends on each of them:

DependencyThe session starts once the dependency…
service without readyhas been launched
service with readypasses its probe
taskhas exited with code 0
  • The probe command is retried every second, with the shell, directory and environment of its session. An attempt still running after 10 s is killed, then retried.
  • A task that succeeded is not run again for its dependents while the daemon runs and its launch definition is unchanged; its own dependencies are still started and waited for. Starting or restarting the task itself always runs it.
  • A task you stop does not count as succeeded, even if it exits with code 0.
  • Starting a session while one of its dependencies is stopping starts that dependency again once it has exited.
  • If a task fails, a probe times out or a dependency stops before being satisfied, the session is blocked and shows why. It starts once the dependency succeeds; starting it again retries.
  • Starting a running service whose probe timed out retries the probe without restarting it.
  • Stopping a waiting or blocked session cancels its start.
  • Stopping or restarting a dependency does not affect the sessions that depend on it.
  • An unknown name or a dependency cycle is a config error.

User settings

Stored in $XDG_CONFIG_HOME/lazyshell/config.yaml (default ~/.config/lazyshell/config.yaml):

language: en   # en (default) or fr

An unknown key or value is an error, so typos are not silently ignored.
