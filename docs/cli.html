Command line

All subcommands take an optional [path] (file or directory) to pick the project; the default is the current directory.

CommandDescription
lazyshell [path]Open the TUI (starts the daemon if a lazyshell.yml is found; from outside a project, attaches to a running daemon).
lazyshell statusSessions of the project: group, state, PID, CPU, memory, listening ports.
lazyshell ps [-a]Sessions of all daemons, like docker ps (-a includes stopped ones).
lazyshell start|stop|restart <name> [-g]Act on a session, or a group with -g.
lazyshell kill [-a]Stop every running session of the project (-a: of all projects).
lazyshell logs <name> [-f] [-n N] [--raw]Print the output as plain text; -f follows, -n limits to the last N lines, --raw keeps ANSI sequences.
lazyshell env <name>Print the environment injected into a session (KEY=value).
lazyshell reloadRe-read the config and apply it to the running daemon.
lazyshell upStart the daemon in the background, without the TUI (runs until down).
lazyshell downStop all sessions, then the daemon.
lazyshell update [--version TAG]Update to the latest release (re-runs the install script in place).
lazyshell daemon [--auto-exit]Run the daemon in the foreground (the TUI normally spawns it).

Examples

lazyshell up                  # start the daemon, no TUI
lazyshell start api           # start one session
lazyshell restart backend -g  # restart a whole group
lazyshell logs api -n 100     # last 100 lines
lazyshell logs api -f         # follow, like tail -f
lazyshell env api             # what the session receives
lazyshell down                # stop everything

logs and env give scripts and AI agents a way to read a session without a terminal. Errors are printed on one line on stderr (lazyshell: context: cause) with exit code 1.
